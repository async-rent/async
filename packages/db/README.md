# @async-rent/db

The Drizzle D1 schema — tables and their inferred types — and nothing else. No
services, no queries: `packages/core` owns those and is the only package that
talks to the database.

```
src/schemas/   one file per table group, re-exported from src/index.ts
migrations/    SQL generated by drizzle-kit; applied by the root wrangler config
seed.sql       the launch catalog, applied outside migration tracking
```

## Migrations

`drizzle.config.ts` generates SQL from `src/schemas` into `migrations/`. It holds
no credentials and does not apply anything:

```sh
vp run generate   # drizzle-kit generate
```

The root `wrangler.jsonc` owns the databases and applies the SQL — one database
per environment:

```sh
wrangler d1 migrations apply async-rent --local          # default, local
wrangler d1 migrations apply async-rent --remote         # default, remote
wrangler d1 migrations apply async-rent_dev --local --env dev
wrangler d1 migrations apply async-rent_staging --local --env staging
```

## Seed

`seed.sql` fills the catalog with the real starting stock: the four launch
cities, nine gear categories and 25 curated monis.rent products (photos, specs,
highlights and per-city weekly prices). Da Nang has no published price sheet
yet, so its rows mirror another city — see the file header.

Prices keep the currency of the sheet they come from: Bali and Chiang Mai are
priced in USD, Lisbon in EUR (monis.rent's Lisbon merchant is EUR-denominated),
so nothing is converted. A price row, a cart, a rental and a payment each
carry one currency.

The 50 product photos live in the `async-rent-products` R2 bucket under the
`products/images/` key prefix, and the seed's `product_images.url` rows hold
the matching site paths (`/products/images/<sequence>.jpg`). No worker binds
that bucket yet — the storefront that will serve the photos is still to come.

It bypasses migration tracking on purpose, so apply it with `wrangler d1 execute`
after the schema is up to date:

```sh
wrangler d1 execute async-rent --local --file=packages/db/seed.sql
wrangler d1 execute async-rent --remote --file=packages/db/seed.sql
```

Add `--env dev` or `--env staging` for the other environments. Every statement
upserts, so re-running is safe; rows are updated in place rather than inserted
twice.
